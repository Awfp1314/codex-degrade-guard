# 鹈鹕骑车测试（手动体检）

这是账号体检，不是写前闸门。写/删前的降智检查由插件钩子自动完成，不要在这里重复。

## 原则

- 必须使用固定原句，不能添油加醋，也不能有其他 skill 干扰会话。
- 空会话、不带历史记忆。
- **判定只看生成出来的画面，不看首段关键词。** 旧口径（内嵌 SVG / 循环 / 踩踏）只能当旁证，不能当结论。
- 未见降智通常要约 **8 分钟** 才画完；探针超时默认 12 分钟。先告诉用户「会比较久」，再调用工具。

## 怎么看画面

看**画质**，不要只看「鹈鹕在不在车上」。贴纸风、几何色块、简陋 SVG，即使骑在车上也算降智。

- **未见降智：** 完整插画。有设计（标题/文案排版、光影、环境细节），鹈鹕在骑车（脚和踏板对得上），看上去像一张用心做的海报。通常要约 8 分钟。
- **疑似降智（满足一条就判）：**
  - 人和车分离（飞在天上、车空在路上）
  - 贴纸 / 简笔画 / 色块拼贴，一眼很糙
  - 缺背景或明显没画完
  - 很快交卷，画面却很简陋

拿不准时判**疑似降智**，不要因为「骑在车上 + 有天空」就判未见降智。
不要根据文案里有没有「内联 SVG」或「循环」下结论。

## 怎么做

1. 先告诉用户：这次会另起空会话作画，未见降智大约 8 分钟，请等。
2. 调用 MCP 工具 `model_degradation_guard.pelican_probe`。默认就是 `gpt-6-astra` + `medium`，**不要改成当前对话里的模型**。只有用户明确要求换模型或思考强度时才传 `model` / `reasoning_effort`。
3. 如果 MCP 不可用，直接运行：

```bash
node "${PLUGIN_ROOT}/probes/pelican.cjs"
```

Windows PowerShell：

```powershell
node "$env:PLUGIN_ROOT\probes\pelican.cjs"
```

4. 探针返回后：
   - 有截图路径：用 Markdown 把图画出来 `![鹈鹕骑车](截图绝对路径)`，再按上面的画面标准判定。
   - 没有截图：把 HTML 路径给用户，能打开就打开，你也要看画面再下判断。
5. 把画面、判定、用时如实告诉用户。关键词旁证可以提一句「仅供参考」，不要写成结论。
6. 单次结果不能当作「必须停手」的理由，只作为是否换模型/检查账号的参考。
