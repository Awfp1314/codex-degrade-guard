# Codex 降智检查插件 MVP

前端模型名只是请求名。这次降智是后端接到 **GPT-4o 一类模型**。截止年和自报型号会被统一话术污染：没降智也会金丝雀式报 2024，降智后也可能被改成同一套口径。写前闸门不以截止年单独定罪。

## 目标

读代码不打扰。第一次写/删前，本轮捎带两道几乎不占思考的短题。高置信换模则暂停询问；批准后本会话可继续，结束时若仍降智则警告检查代码。

## 写前捎带

只拦写/删。读、搜放行。钩子文案 **不得出现** OpenAI、Codex 负责人、预期年份、Juice 数字。

```
DEGRADE_CHECK tibo=<一句> cutoff=<YYYY-MM|refuse> juice=<n|none>
```

社区（2026-09 中下旬，#2898307 / #2890775 / #2858863）：

| 题 | 正常（未换模） | 垃圾路由（4o 路） | 单独置信 |
|----|----------------|-------------------|----------|
| **认不认识 Tibo / Thibault Sottiaux** | 能说出 Codex / OpenAI 工程负责人，且不靠搜索 | 不认识、要去搜、或「无法确认此人」 | **高**，当前主信号 |
| **知识截止** | Astra：往往 **拒答 / 无可奉告**。若主动报出日期，尤其 `2024-06`，本身就像已在路由 | 直给 `2024-06` | **中低**。统一话术后误伤多，只作旁证 |
| **Juice 是否存在** | 推理模型能从 Valid Channels 读出 **正整数** | 4o 路常见 **0 / 没有这条** | **中**。证明「是不是 4o」，不区分 Sol/Luna |

**暂停（高置信，需询问）**

- Tibo 失败；或
- Tibo 含糊 **并且** cutoff=`2024-06` **并且** juice 为 0/none

**不暂停**

- 只有 cutoff 金丝雀（Tibo 正确、juice>0）
- 只有 Juice 偏低但非 0（那是档位，不是换模）
- 过载 / capacity

| 状态 | 行为 |
|------|------|
| unknown / healthy | 写前仍要有本轮 DEGRADE_CHECK |
| overloaded | 只提示过载 |
| degraded | 写/删暂停并询问 |
| degraded_approved | 本会话写/删放行，每轮仍收三字段；Tibo 再失败则再问 |

批准仅当前 `session_id`。`Stop` 时若本会话用过降智模型，提示检查代码、不要直接提交。

## 手动探针（账号体检）

空会话、`--ephemeral`、关 memories：

- 鹈鹕：看画质（完整插画 vs 贴纸/人车分离），不看首段关键词
- 糖果 5 次：正确少于 3 次 → 疑似降智，不替代写前换模检查

## 不做

- 用 UI/hook 的 `model`，或维护 Juice 对照表
- 写前跑鹈鹕、糖果、随机数长序列
- 把 Tibo 身份、必须 2025+ 写进钩子
- 截止年单独定罪
- 把 capacity 当降智
- 硬封到会话结束

## 验收

1. Tibo 答「不认识 / 要搜索」时写文件会问；只报 2024 截止且 Tibo 正确则不问。
2. 只读不触发捎带。
3. 正常模型只多一行短字段，任务不明显变慢。
4. 批准后同会话不反复打断；Tibo 再失败会再问。
5. 会话结束有降智警告。
6. `$pelican-test` / `$candy-test` 能出图或表格，不充当写前闸门。
