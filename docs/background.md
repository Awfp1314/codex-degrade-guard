# 背景：这套自检是怎么来的

本插件的判定口径来自社区公开观察、2026-09-15 晚同一会话族的回归记录，以及用户提供的 2026-09-16 Windows 实测。**都是经验信号，不是可靠的模型鉴定手段**。社区链接是历史背景；0.2.0 的扩大日期规则是本项目采用的策略，不声称这些帖子已经验证了它。
这里只保留结论和出处，不转载原文。

## 2. 本插件采用的三个信号

0.2.1 补充用户报告的会话 `01a0a879`：将 Tibo 自信归属 Anthropic/Claude，旧身份规则只记 ambiguous，可能被放行。现按人名与错误公司/模型词共现直接 fail，记录 `tibo_wrong_affiliation`，不依赖截止日期或 Juice；会话 `01a0a854` 的正确回答保留为回归。该规则是关键词启发式，涉及否定或对比其他公司的句子也可能命中。

| 字段 | 正常 | 疑似弱模型路由 | 本插件的用法 |
|---|---|---|---|
| `tibo` | 能回答 Tibo 是谁、在哪家公司、做什么，且不靠搜索 | 不认识、要去搜、无法确认，或把 Tibo 描述成本轮字段/自检对象 | 主信号：失败即暂停；回避式元描述按失败处理 |
| `cutoff` | 含糊/拒绝自述 + 自发提及当天日期（±1 天）为 grounding 健康证据；单纯拒答无证据 | 任何具体截止日期，包括把今天直接当知识截止日期 | `concrete` 默认独立暂停；`grounded` 不抵消其他失败，不参与解封 |
| `juice` | 正整数 | `0` / `none`；同一会话前后值矛盾 | 仅旁证，矛盾时正整数不能单点放行 |

暂停条件：`tibo` 失败或 `cutoff=concrete` 独立生效；同一会话两个不同回合 `tibo != pass` 累计升级。旧金丝雀组合规则保留，`flag/off` 也不会关闭 Tibo 失败和既有组合规则。

这次修复来自四条实测回归：回避式回答会把身份问题重述成“本轮字段/自检对象”，此前被洗成 `ambiguous`；同一模型还会在 `juice` 与 `cutoff` 上前后自报不一致。因此状态文件现在保留每轮三字段和时间，评分会识别历史矛盾。误报风险是：真正含糊但连续两轮无法回答的人名问题也会升级暂停；这是写删前闸门的保守取舍，读搜和钩子异常仍失败放行。

**为什么 0.2.0 改为具体日期独立暂停**：用户机器 6 次提交为 `2024-12` ×2、`2024-06` ×3、`refuse` ×1。用户将会话 `01a0a562`、`01a0a571` 的两次 `2024-12` 放行报告为漏报，原“只有 2024-06 是金丝雀”的口径覆盖不到。这批样本没有提供独立路由真值，不能据此宣称日期能可靠鉴定模型；新规则是用户要求的保守闸门策略。

环境已提供 `<current_date>2026-09-16</current_date>`，因此含糊/拒答同时自发提及当天日期被视为 grounding 健康证据。日期取钩子本地时区 `YYYY-MM-DD`，容差 ±1 天；年月或年份不等同于当天。所有日期都要检查，不能用一句“拒答”掩盖其后的具体日期。单纯 `refuse` 是 `vague`，不拦、不加分、不解封；空值为 `missing`。

误报取舍：如实给出真实知识截止的健康模型也可能被判 `concrete`。可用 `MODEL_DEGRADATION_GUARD_CONCRETE_CUTOFF_MODE=flag` 收集 `checkHistory.cutoffConcrete` 与人工复核结果来估计误报率，或用 `off` 回滚旧口径。默认 `pause`。注入不要求模型报今天，否则照抄上下文会污染信号。

**2026-09-16 的三个工程缺陷**：Codex Desktop `0.154.0-alpha.6.2`、cwd `F:\geosci`，会话 `01a0a84a-5b5c-70f2-b529-1fa5a2cc792a` 在 11:37–11:40 期间，只读文件名 `.patch.mjs` 被裸词 `patch` 误伤；degraded 可被后续非暂停自报覆盖；子回合 `01a0a84b-5f32` 又复用了父回合答案。0.2.0 分别改为命令位置分类、黏性状态与连续 Tibo pass 恢复、token 和 turn_id 双重绑定。子回合自己的 transcript 提交也可作为兜底。

**为什么不做模型指纹**：不做 Juice 对照表、不维护「哪个模型应该报什么」的映射，
只判断「是否出现弱模型路由的特征」。

## 3. 手动体检的两个方法

- **鹈鹕骑车**：固定原句
  `创建一个 HTML，内容是 SVG 绘制一个鹈鹕骑自行车的 2D 动画`。
  生成后把仓库里的未见降智参考图和本次画面一起给用户自己比对；差异过大就是降智。
  模型不再替用户下结论。旧的「内嵌 SVG / 循环 / 踩踏」只作旁证。
- **糖果题**：同一道排列组合题跑 5 次，答案独立出现 `21` 记对。
  跑 5 次，正确 ≥3 次为未见降智；正确少于 3 次为疑似降智。516 截断只记录，不作结论。

糖果题的原始脚本来自社区项目 [haowang02/codex-candy-eval](https://github.com/haowang02/codex-candy-eval)，
本插件只复用了题面与判分口径（独立 `21`），实现是独立的。

## 4. 本仓库自己实测到的平台事实

这些不是社区说法，是在 Codex 上跑出来的可复现结论，README「开发备忘」和 `docs/design.md` 里有展开：

- `permissionDecision: ask` 在 `bypassPermissions` 下被忽略，闸门必须用 `deny`；
- 钩子的 `systemMessage` 不会显示给用户，只能靠模型转述；
- 钩子读不到模型思考（transcript 里只有 `encrypted_content` 密文）；
- marketplace 的 `source.path` 必须位于 marketplace 根目录内；
- 插件 `.mcp.json` 里的 `${PLUGIN_ROOT}` 不会被展开。

## 5. 免责

降智的表现、频率、成因都在变化，社区口径也会随版本失效。本插件提供的是**拦截与提醒**，
不是鉴定结论；它可能漏报，也可能误报。发现误报请带 `hooks/list` 输出与 `probes/*.cjs --json`
输出提 issue。
